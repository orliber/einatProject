# שחרור גרסה חדשה לעינת (D-033, D-091)

עינת לא צריכה לעשות כלום: הגרסה יורדת ונבדקת אצלה ברקע, מופיע "✦ גרסה חדשה מוכנה", והיא לוחצת "להפעיל מחדש ולעדכן" (D-038).

## איך זה עובד, בקצרה

- **כל מיזוג ל-`main`** בונה ב-GitHub את המתקין ל-Windows בדיוק כמו בשחרור, ומריץ עליו את כל בדיקות השחרור (FIPS, 0 דליפות, כל הכספות הישנות, התקנה נקייה והקלדה של 500 תווים בחלון). אם משהו נשבר, רואים את זה מיד אחרי המיזוג, לא ביום השחרור.
- **השחרור לא בונה כלום.** הוא לוקח את המתקין שכבר נבדק לאותו commit, חותם ומפרסם. כמה דקות.
- **כל PR** בודק שהגרסה ב-`main` מוכנה לשחרור: מספר גרסה זהה בשלושת המקומות, קובץ "מה חדש" (`release-notes/<גרסה>.txt`) וכספת שמורה לגרסה.

## כל גרסה (כמה דקות)

1. **PR של גרסה:** `scripts/release.sh bump 0.8.0`, או לבקש מ-Claude "תעלה גרסה ל-0.8.0" עם רשימת מה חדש. ה-PR מעדכן את מספר הגרסה, מוסיף `release-notes/0.8.0.txt` (שורה לכל שינוי, בעברית פשוטה לעינת) ואת הכספת השמורה של הגרסה. ממזגים אותו.
2. **מחכים ש-CI על `main` יהיה ירוק** (הוא בונה את המתקין שישוחרר).
3. **משחררים**, באחת משלוש דרכים:
   - ב-GitHub: Actions ← Release ← Run workflow (על `main`) ← Run workflow.
   - או לבקש מ-Claude "תשחרר את הגרסה".
   - או במק: `scripts/release.sh 0.8.0`.
4. השחרור בודק שהמתקין של אותו commit ובאותה גרסה, חותם את הודעת העדכון ובודק אותה בקוד של התוכנה עצמה, ומפרסם בשני מקומות: כאן (קישור קבוע, D-026) ובריפו ההתקנות. אצל עינת: בבדיקה היומית הבאה, או מיד מ"הגדרות ← עדכונים ← בדיקת עדכונים".

**חזרה בלי לפרסם:** Actions ← Release ← Run workflow ← לסמן "חזרה בלבד". עובר את כל השלבים, חותם במפתח חד-פעמי שהתוכנה מסרבת לו, ומשאיר את מה שהיה מתפרסם להורדה. אפשר על כל ענף שהריצו עליו CI (Actions ← CI ← Run workflow).

## פעם אחת: לתת ל-GitHub לשחרר לבד

צריך את זה רק פעם אחת, במק של אור, שבו נמצא מפתח החתימה:

1. `scripts/release.sh secrets`
   - מעלה את מפתח החתימה כסוד מוצפן `DV_UPDATE_SIGNING_KEY` (בלי להציג אותו).
   - מבקש טוקן לפרסום בריפו ההתקנות ושומר אותו כסוד `RELEASES_REPO_TOKEN`. יוצרים אותו ב-GitHub: Settings ← Developer settings ← Fine-grained tokens ← Generate new token; Repository access: רק `orliber/einat-vault-releases`; Permissions: Contents ← Read and write; תוקף שנה.
2. לוודא שבכל חשבון עם הרשאת כתיבה לריפו יש אימות דו-שלבי (2FA): מי שנכנס לחשבון כזה יכול להפיץ גרסה.

בלי השלב הזה השחרור מ-GitHub נעצר בשלב החתימה עם הודעה ברורה, ואפשר לשחרר מהמק: `scripts/release.sh 0.8.0 --sign-here` (מוריד את המתקין הבדוק, חותם במק ומפרסם; גם זה כמה דקות).

## ההקמה הראשונה (נעשתה כבר)

1. במק: `brew install gh`, ואז `gh auth login`.
2. מהתיקייה של הפרויקט: `scripts/release.sh setup`
   - יוצר מפתח חתימה ב-`~/.diagnostic-vault/update-signing.pk8`. **לגבות אותו** לדיסק נייד שנשמר במקום בטוח. בלי המפתח אי אפשר לעדכן את עינת מרחוק, וצריך התקנה ידנית מחדש.
   - כותב את המפתח הציבורי ל-`crates/dv-egress/update_key.pub`.
   - יוצר את הריפו הציבורי `orliber/einat-vault-releases` (רק מתקינים, בלי קוד).
3. מכניסים את `crates/dv-egress/update_key.pub` ל-`main` ב-PR רגיל. זה רק המפתח הציבורי.
4. **ההתקנה הראשונה אצל עינת** צריכה להיות גרסה שכבר כוללת את המפתח: עינת מתקינה אותה פעם אחת ידנית מהריפו הציבורי (`DiagnosticVault-Setup.exe`). מאותו רגע, כל עדכון מגיע מתוך התוכנה.

### מפתח שני וגיבוי מוצפן (פעם אחת, אחרי ה-setup)

5. **מפתח הבא:** `cargo xtask update-keygen --next`. נוצר `~/.diagnostic-vault/update-signing-next.pk8`, והמפתח הציבורי שלו נכתב כשורה שנייה ב-`update_key.pub`. מכניסים ל-`main` ב-PR ומשחררים גרסה. מאותו רגע התוכנה אצל עינת מקבלת חתימה של כל אחד מהשניים, כך שאם הראשון אבד או דלף אפשר לעבור לשני בלי התקנה ידנית. **את המפתח השני לא מעלים כסוד:** הוא נשאר רק אצל אור, למקרה שהסוד ב-GitHub דלף.
6. **גיבוי מוצפן לכל מפתח:** `cargo xtask update-key-backup /Volumes/<דיסק נייד>/update-signing.dvkey` (ולמפתח השני: `DV_UPDATE_KEY=~/.diagnostic-vault/update-signing-next.pk8 cargo xtask update-key-backup …`). מבקש משפט-סיסמה של 12 תווים לפחות, מצפין באותה שיטה כמו הכספת (Argon2id + AES-256-GCM), ובודק שהעותק נפתח ושהמפתח שבו נעוץ בקוד. את משפט-הסיסמה כותבים על נייר ושומרים **בנפרד** מהדיסק.
7. **שחזור:** `cargo xtask update-key-restore <קובץ-הגיבוי> ~/.diagnostic-vault/update-signing.pk8`. נכשל אם משפט-הסיסמה שגוי או אם המפתח לא נעוץ בקוד.

## אם משהו השתבש

- **"no checked installer for … yet":** CI על `main` עוד בונה את המתקין, או שנכשל. מחכים שיהיה ירוק (Actions ← CI), ומריצים את השחרור שוב. אם הוא אדום, מתקנים ב-PR רגיל; המתקין הבא נבנה אחרי המיזוג.
- **"The version on main can be released" אדום ב-PR:** חסר `release-notes/<גרסה>.txt`, חסרה הכספת השמורה, או ששלושת מספרי הגרסה לא זהים. ההודעה אומרת מה להריץ.
- **"the private key does not match":** המפתח בסוד (או במק) לא תואם את המפתח הציבורי בקוד. לא לפרסם. להריץ שוב `scripts/release.sh secrets` מהמק עם המפתח הנכון.
- **"the secret … is missing":** לא נעשה השלב "פעם אחת" למעלה. בינתיים: `scripts/release.sh <גרסה> --sign-here` מהמק.
- **"already published":** הגרסה כבר יצאה. גרסה חדשה צריכה מספר חדש (`bump`).
- **"parser pins: … is not in supply-chain/parsers.txt":** עודכנה גרסה של ספרייה שקוראת קבצים מבחוץ (PDF, Word, גופנים, מודל השמות). קוראים מה השתנה בה, ואם זה בסדר מוסיפים את השורה (שם, גרסה, checksum מ-`Cargo.lock`) ב-PR.
- **גרסה חדשה לא פותחת את הכספת אצל עינת (R7):** במסך הנעילה מופיע אצלה "הכספת לא נפתחה בגרסה הזו" עם כפתור לדף הגרסאות. היא מורידה את הגרסה הקודמת ומתקינה מעל, והכספת נפתחת בה (המתקין מאפשר חזרה אחורה ולא נוגע בתיקיית הכספת). בינתיים כדאי למחוק את ה-release השבור מ-`orliber/einat-vault-releases`, כדי שהגרסה הקודמת לא תציע לה אותו שוב, ולשחרר תיקון עם מספר גבוה יותר. מיגרציה של הכספת רק מוסיפה טבלאות ועמודות (נבדק), ולכן גרסה קודמת יכולה לפתוח אותה.
- **גרסה עם באג כבר פורסמה:** לא מורידים גרסה אחורה, כי התוכנה מסרבת ל-downgrade בכוונה. משחררים מיד גרסה עם מספר גבוה יותר.

## אם המפתח דלף

0. **קודם כל:** מוחקים את הסוד `DV_UPDATE_SIGNING_KEY` מהריפו (Settings ← Secrets and variables ← Actions), ובודקים ב-Actions אם רץ שחרור שלא אתם הפעלתם.
1. **אם כבר יש מפתח שני נעוץ (שלב 5):** מוחקים את המפתח שדלף, מעבירים את השני למקומו (`mv ~/.diagnostic-vault/update-signing-next.pk8 ~/.diagnostic-vault/update-signing.pk8`), מוחקים מ-`update_key.pub` את השורה של המפתח שדלף, ומריצים `cargo xtask update-keygen --next` כדי לנעוץ מפתח הבא חדש (ולגבות אותו, שלב 6). משחררים גרסה (`--sign-here`, או אחרי `scripts/release.sh secrets` עם המפתח החדש). אין צורך בהתקנה ידנית.
2. אחרת: יוצרים מפתח חדש (מזיזים את הישן ומריצים `setup`), עושים commit למפתח הציבורי החדש, ומשחררים גרסה **חתומה במפתח הישן** שכבר כוללת את החדש. זו החתימה האחרונה של המפתח הישן.
3. אם המפתח הישן לא זמין, או שהגרסה כבר הופצה על ידי מי שהשיג אותו: עינת מסירה ומתקינה ידנית גרסה חדשה מהריפו. הכספת נשארת במחשב, והתקנה מחדש לא מוחקת אותה.
4. לתעד ב-`docs/compliance/INCIDENT_RESPONSE.md`.

## כניסה עם גוגל כששוכחים סיסמה (D-041) – הגדרה חד-פעמית
בלי השלב הזה התוכנה פשוט לא מציגה את האפשרות. זה רישום של התוכנה אצל גוגל, לא חשבון של עינת.
1. ב-Google Cloud Console: פרויקט חדש (למשל "DiagnosticVault").
2. "APIs & Services ← Library": להפעיל את **Google Drive API**.
3. "OAuth consent screen": סוג External, שם "כספת האבחון", ובהרשאות רק `openid` ו-`.../auth/drive.appdata`. במצב Testing מוסיפים את כתובת הגוגל של עינת ל-Test users (מספיק לשימוש שלה, והתוכנה לא שומרת טוקנים).
4. "Credentials ← Create credentials ← OAuth client ID ← Desktop app".
5. את ה-Client ID ואת ה-Client secret שמים ב-GitHub: Settings ← Secrets and variables ← Actions, בשמות `DV_GOOGLE_CLIENT_ID` ו-`DV_GOOGLE_CLIENT_SECRET`. הגרסה הבאה שתשוחרר כבר תציע את האפשרות.

גוגל מתייחסת ל-secret של אפליקציית דסקטופ כגלוי, ולכן אין בעיה שהוא בתוך התוכנה. ההגנה היא PKCE, וזה שהמפתח בגוגל לבדו לא פותח את הכספת.
