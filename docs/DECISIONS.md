### D-012 · כניסה לתוכנה – 2026-09-28 (סבב ייעוץ 2; מחליף את D-007)
הנחיה: "אימות טוב ונכון לסיטואציה, לא מוגזם". המטרה היא שהעבודה בתוכנה תהיה מוצפנת, לא להקשות על עינת.
1. **"חריצי מפתח" (כמו LUKS): Windows Hello (PIN / פנים) או Touch ID כדרך היומיומית, סיסמה לתוכנה כגיבוי, וערכת שחזור מודפסת** ✔
2. סיסמה ארוכה + סוד חומרה בכל פתיחה (D-007 המקורי): נדחה כמוגזם.
3. כניסה עם חשבון Google: נדחה. מחייב אינטרנט בכל פתיחה, חושף ל-Google מתי עינת עובדת, ולא מייצר מפתח הצפנה.
**פירוט:** מפתח-העל (MK) עטוף בנפרד בכל "חריץ": `password` (Argon2id, 12 תווים לפחות, חסימת סיסמאות נפוצות, הצעה לביטוי-סיסמה), `recovery` (256 ביט), `windows_hello` / `macos` (מפתח שקשור לחומרה ודורש נוכחות).
**מימוש בשלבים:** סיסמה וערכת שחזור בשלב 2. Windows Hello ו-Touch ID בשלב 2ב, כי הם דורשים בדיקה על מחשב Windows או Mac אמיתי.
**סטייה מתועדת מ-NIST 800-63B-4** (15 תווים לסיסמה כגורם יחיד): ההחלטה היא 12, בגלל פרמטרים חזקים של Argon2id וכי Windows Hello הוא הדרך העיקרית.
