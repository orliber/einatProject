# סקירה ביקורתית של הארכיטקטורה המוצעת (שלב 0)

> תוצר של שלב 0 לפי `START_HERE.md`. ההחלטות שהתקבלו מתועדות ב-`DECISIONS.md`, והארכיטקטורה המעודכנת ב-`ARCHITECTURE.md`.

## 1. מה מצוין בערכה ונשאר כמו שהוא
- **Fail-closed** ושער אחד שדרכו חייב לעבור כל טקסט.
- **תגיות יציבות** לכל תיק. ההודעות והטיוטות נשמרות **עם תגיות בלבד**, כך שהכספת עצמה כבר מכילה מידע בשם בדוי.
- **"ה-AI מנסח, עינת מאבחנת"**: פרשנות ציונים דטרמיניסטית, `[חסר: ...]` במקום המצאה, ואישור לכל פסקה.
- **מסך "מה יוצא מהמחשב"** כברירת מחדל קבועה.
- crypto-shredding עם מפתח לכל תיק, audit עם שרשרת, וסירוב לפעול בתיקייה שמסונכרנת לענן.
- חבילה אדוורסריאלית, canary ו-property tests, עם **0 דליפות** כתנאי למיזוג.
- פרופיל סגנון במקום טקסט מלא של דוחות קודמים, ובדיקת זליגה ב-n-grams.

## 3. השוואת טכנולוגיות

ציונים 1–5 (5 = הכי טוב). המשקלות נקבעו לפי העיקרון "אבטחה וחיסיון קודם".

| קריטריון (משקל) | **Tauri + Rust בלבד** ✔ | Tauri + Rust + Python מבודד | Tauri + Python (הערכה המקורית) | Electron + TS |
|---|---|---|---|---|
| בידוד רשת ומפתחות (×3) | **5**: רשת ב-crate אחד, אכיפה בקומפיילר וב-CI | 4: Python בלי רשת (firewall), אבל עוד תהליך | 2: Python מחזיק הכל | 2: Node עם גישה מלאה לרשת ולקבצים |
| משטח תקיפה ושרשרת אספקה (×3) | **5**: בינארי אחד, crates מעטים | 3 | 2: PyInstaller + עשרות תלויות | 1: Chromium + Node + npm |
| היגיינת זיכרון לסודות (×2) | **5**: zeroize, mlock | 4 | 1: אין מחיקה אמינה ב-Python | 2 |
| קריפטו מאומת FIPS (×2) | **5**: aws-lc-rs | 5 | 3 | 3 |
| עברית: NER / OCR / PDF (×2) | 4: ort + tokenizers, pdfium, tesseract כ-helper | **5** | 5 | 3: transformers.js, tesseract.js |
| Word: תבנית + הצפנה (×1) | 3: מימוש שלנו, נבדק מול msoffcrypto ו-LibreOffice | 5 | **5** | 3 |
| מהירות פיתוח (×1) | 3 | 2: שלוש שפות | **5** | 4 |
| הפצה (חתימה, AV false-positive) (×1) | **5** | 2 | 2: PyInstaller נחסם לעיתים | 4 |
| **סה"כ משוקלל (מתוך 75)** | **69** | 58 | 42 | 36 |

**ההחלטה:** Tauri 2 + Rust + React/TS (D-002).

**המחיר, בגלוי:**
- הצפנת Word (ECMA-376 Agile) נכתבת אצלנו. היא נבדקת ב-CI מול `msoffcrypto-tool` (כלי פיתוח בלבד, לא נארז) ומול פתיחה ב-LibreOffice.
- OCR: Tesseract כבינארי helper חתום, שרץ בתוך ה-worker המבודד.
- בשלבים 2–4 הפיתוח איטי יותר. היתרון: אין שכבת IPC מול sidecar, ואין בעיות אריזה של Python.
